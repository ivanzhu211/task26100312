# audience — 进程内存受众匹配库

由上层竞价引擎直接以 Go 包形式调用，无接口层，数据全部保存在进程内存。

## 能力

- `Load([]Ad)`：载入一批广告规则（每条广告 = 唯一整数 ID + 布尔表达式），载入后规则不再修改。
- `Match(tags []int64) []int64`：返回所有且仅有表达式为真的广告 ID（升序、不截断）。空标签集合也可能命中。
- `Explain(adID, tags) *Explanation`：解释指定广告为何匹配/不匹配。解释树与原表达式逐位置同构，
  覆盖每个标签与运算符的出现位置并给出该处真值，不做短路裁剪；根位置真值与 `Match` 结果一致。

## 表达式

```go
audience.Tag(7)                    // 标签叶子
audience.And(a, b, c ...)          // 合取，>=2 操作数
audience.Or(a, b, c ...)           // 析取，>=2 操作数
audience.Not(a)                    // 否定，恰好 1 操作数
```

## 匹配加速原理

- 载入时构建 标签 -> 广告 的倒排索引（含 NOT 内部的标签出现），并预计算“全假赋值下为真”的恒真广告集合。
- 匹配时只对请求标签涉及的广告逐条求值；请求未涉及且恒真的广告直接命中——
  否定条件不会被跳过：NOT 内标签同样进入倒排索引，一旦请求涉及该标签，广告必然被重新求值。
- `Match`/`Explain` 不修改引擎状态，连续请求互不影响（仅支持顺序调用）。

## 测试

```sh
go test ./...          # 全部测试（含规模与性能测试）
go test -short ./...   # 跳过规模测试
go test -run TestScaleAndPerformance -v ./...   # 查看实测载入/匹配/内存指标
```

覆盖：嵌套 NOT、恒真/恒假、重复子表达式、连续不同请求、空标签集合、命中与未命中的逐位置解释、
32 组二选一规则，以及随机表达式与逐条直接求值的对拍。

规模实测（Apple Silicon，100000 条广告 / 609 万出现位置 / 100 万标签）：

- 载入：约 0.76s（约束 30s）
- 1000 次匹配（每次 50 标签）：总耗时约 0.17s，单次最大约 0.27ms（约束 10s / 100ms）
- 载入后堆内存：约 448MiB（约束 1GiB）
